## 3. Contexto Cyber Kill Chain

**Fase:** Installation / Actions on Objectives

**Contexto:**  
La creación de cuentas locales privilegiadas puede representar una acción de persistencia posterior al acceso inicial. En este caso, la actividad ocurre fuera de horario laboral y combina creación de cuentas, modificación de grupos administrativos, ejecución de comandos mediante `net.exe`, autenticación remota y uso de credenciales explícitas.

---

## 4. Objetivo del hunt

Identificar actividad sospechosa relacionada con creación, habilitación y uso de cuentas locales fuera de horario laboral, especialmente cuando una cuenta recién creada es agregada al grupo local `Administrators` y posteriormente utilizada para autenticación remota o creación de nuevas cuentas.

---

## 5. Hipótesis de caza

Durante una ventana fuera de horario laboral, un actor con acceso previo al host podría crear una cuenta local, habilitarla, agregarla al grupo `Administrators` y utilizarla para mantener persistencia o preparar actividad posterior.

La hipótesis gana fuerza si la cuenta recién creada:

- es agregada rápidamente al grupo `Administrators`
    
- ejecuta acciones administrativas adicionales
    
- realiza autenticación remota mediante Logon Type 3
    
- aparece asociada a uso de credenciales explícitas
    
- crea o privilegia nuevas cuentas locales

## 9. Lógica de detección

La lógica principal no se basa en un evento aislado, sino en una secuencia de comportamiento.

**Secuencia sospechosa esperada:**

1. Creación de cuenta local  
    `Event ID 4720`
    
2. Habilitación de la cuenta  
    `Event ID 4722`
    
3. Adición de la cuenta al grupo local `Administrators`  
    `Event ID 4732`
    
4. Ejecución de comandos administrativos mediante `net.exe`  
    `Event ID 4688`
    
5. Uso posterior de la cuenta mediante autenticación remota  
    `Event ID 4624 / Logon Type 3`
    
6. Uso de credenciales explícitas o creación de nuevas cuentas  
    `Event ID 4648 / 4720 / 4732`
    

**Ventana de correlación recomendada:**

```text
10 a 30 minutos
```

**Condiciones de mayor sospecha:**

- actividad fuera de horario laboral
    
- cuenta creada y privilegiada en pocos minutos
    
- uso de `net.exe`
    
- autenticación remota posterior
    
- creación encadenada de una segunda cuenta privilegiada
    
- actor inicial distinto a una cuenta de automatización conocida

## 18. Hallazgo principal

Se identificó una secuencia sospechosa de creación, habilitación, elevación y uso de cuentas locales fuera de horario laboral.

La actividad inicia con `administrator`, quien crea y habilita la cuenta `svc_backup_new`, la agrega al grupo local `Administrators` y ejecuta comandos administrativos mediante `net.exe`.

Posteriormente, `svc_backup_new` realiza autenticación remota, aparece asociada a uso de credenciales explícitas y crea una segunda cuenta local llamada `helpdesk_temp`, que también es agregada al grupo `Administrators`.

Este comportamiento es consistente con una posible técnica de persistencia mediante cuentas locales privilegiadas.

---

## 19. Reducción de ruido y falsos positivos

Antes de clasificar el hallazgo como malicioso, se debe validar si la actividad corresponde a una operación autorizada.

**Posibles falsos positivos:**

- tareas de soporte fuera de horario
    
- creación temporal de cuentas administrativas
    
- scripts internos de mantenimiento
    
- actividades de hardening o respuesta a incidentes
    
- automatización mediante herramientas como SCCM, Ansible o scripts de administración
    
- instalación o configuración de software que requiere cuentas locales privilegiadas
    

**Exclusiones recomendadas:**

- cuentas de automatización aprobadas
    
- cuentas administrativas documentadas
    
- hosts de administración conocidos
    
- ventanas de cambio autorizadas
    
- procesos firmados o scripts internos validados
    

---

## 20. Criterios de validación

### True Positive

La hipótesis debe considerarse validada si se confirma una o más de las siguientes condiciones:

- la creación de la cuenta no estaba autorizada
    
- la cuenta fue agregada a `Administrators` sin ticket o cambio aprobado
    
- la cuenta fue usada desde una IP no esperada
    
- la cuenta recién creada ejecutó acciones administrativas posteriores
    
- no existe justificación operacional para la creación de `svc_backup_new` o `helpdesk_temp`
    
- la actividad se asocia a otros indicadores de movimiento lateral, ejecución remota o acceso a recursos compartidos
    

---

### False Positive

La hipótesis debe considerarse descartada si se confirma que:

- la actividad fue parte de una tarea administrativa aprobada
    
- existía un cambio programado
    
- las cuentas fueron creadas por un flujo de soporte documentado
    
- el origen de conexión corresponde a infraestructura interna autorizada
    
- el uso de `net.exe` formaba parte de un script legítimo

## 22. Mitigación recomendada

- Deshabilitar temporalmente las cuentas `svc_backup_new` y `helpdesk_temp` hasta validar autorización.
    
- Revisar membresía del grupo local `Administrators`.
    
- Validar si `administrator` fue usado legítimamente o si sus credenciales fueron comprometidas.
    
- Revisar origen de conexión `192.168.1.55` y `10.0.0.20`.
    
- Implementar o revisar LAPS / Windows LAPS para administración de contraseñas locales.
    
- Restringir modificación de grupos locales mediante GPO.
    
- Auditar privilegios administrativos locales.
    
- Generar una regla de detección basada en creación de cuenta + elevación + uso posterior.

## 23. Limitaciones

Este hunting identifica comportamiento sospechoso, pero no confirma compromiso por sí solo.

Para confirmar compromiso se requiere:

- validación de autorización operacional
    
- revisión del endpoint afectado
    
- análisis de procesos completos
    
- revisión de sesiones activas
    
- validación de IPs origen
    
- análisis de uso posterior de las cuentas
    
- búsqueda de actividad lateral o persistencia adicional

## 24. Conclusión

La investigación identificó una secuencia de alto riesgo relacionada con manipulación de cuentas locales fuera de horario laboral.

Durante aproximadamente 18 minutos, se observó:

- creación de `svc_backup_new`
    
- habilitación de la cuenta
    
- adición al grupo `Administrators`
    
- ejecución de comandos mediante `net.exe`
    
- autenticación remota tipo 3
    
- uso de credenciales explícitas
    
- creación de una segunda cuenta `helpdesk_temp`
    
- adición de la segunda cuenta al grupo `Administrators`
    
- intento posterior de autenticación fallida desde otra IP
    

La actividad observada es consistente con una posible técnica de persistencia mediante cuentas locales, alineada con MITRE ATT&CK `T1136.001 - Local Account`.

Debido a la combinación de creación de cuentas, elevación de privilegios, autenticación remota y creación encadenada de una segunda cuenta privilegiada, el hallazgo debe escalarse a IR/DFIR para validar autorización, origen, alcance e impacto.
